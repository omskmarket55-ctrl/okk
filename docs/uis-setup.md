# Подключение UIS

## 1. Доступ к API

1. Компонент **«Call API Базовый набор»** подключает менеджер UIS.
2. «Администратор» → «Аккаунт» → «Правила и настройки безопасности» → вкладка «API»:
   добавьте IP сервера в белый список.
3. «Аккаунт» → «Управление пользователями»: пользователь для интеграции с галочками «Доступ к Call API»
   и «Доступ по ключу». Ключ показывается один раз — впишите его в `/opt/okk/.env` как `UIS_ACCESS_TOKEN`
   и выполните `cd /opt/okk && docker compose up -d`.

## 2. Виртуальный номер и сотрудники

- «Настройки» → «Перезвоны и телефония»: виртуальный номер UIS, с которого идёт обзвон.
- «Сотрудники» → «Изменить»: ID сотрудника UIS у каждого, кто звонит. Сотрудник принимает звонок в софтфоне UIS.

Звонок: UIS звонит сотруднику, после ответа — клиенту (`start.employee_call`, `first_call: employee`).
Сотруднику показывается виртуальный номер (`show_virtual_phone_number`), номер клиента — нет.
Чтобы номер не был виден и в кабинете UIS, ограничьте операторам доступ к журналу звонков.

## 3. Уведомления о звонках

`install.sh` в конце показывает адрес вида `https://okk.unosystem.ru/hooks/uis/<секрет>`.
В UIS → «Уведомления» создайте HTTP-уведомления (метод POST, JSON) на события «Начало разговора»
и «Завершение звонка» с полями:

| Поле | Значение из UIS |
|---|---|
| `call_session_id` | идентификатор сессии звонка |
| `event` | `talk` для начала разговора, `end` — для завершения, `missed` — для пропущенного |
| `talk_time_duration` | длительность разговора, секунды |
| `call_records` | идентификаторы записей разговора |

Записи разговоров остаются в UIS; прослушивание в кабинете через сервер (без сохранения файлов) —
следующий этап, после проверки на вашем аккаунте.
